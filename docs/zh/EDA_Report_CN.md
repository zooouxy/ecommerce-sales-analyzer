# 探索性数据分析报告
# Exploratory Data Analysis Report


## 1. 项目概述


### 1.1 项目背景

本项目基于 Online Retail 电商交易数据集，
通过探索性数据分析（Exploratory Data Analysis, EDA）
理解交易数据结构、识别数据质量问题，并为后续数据清洗和商业分析提供依据。


EDA阶段主要目标：

- 了解数据规模和字段结构
- 分析数据完整性
- 发现异常数据
- 探索交易行为特征
- 制定合理的数据清洗策略



---

# 2. 数据集概览


## 2.1 数据来源


数据文件：

Online Retail.xlsx

# 4. 数据质量分析


## 4.1 缺失值分析


分析结果：

|字段|缺失数量|
|-|-:|
|Description|1454|
|CustomerID|135080|



---

## 4.1.1 商品描述缺失分析


Description字段存在1454条缺失记录。


由于商品名称用于：

- 商品销售排名
- 商品分析
- 产品洞察


因此缺失商品描述的数据无法支持商品维度分析。


处理方式：

删除Description为空的记录。



---

## 4.1.2 客户编号缺失分析


CustomerID字段存在135080条缺失。


可能原因：

- 非会员客户购买
- 历史交易记录不完整


由于客户编号并非所有交易必须存在，

因此本项目不会直接删除CustomerID缺失数据。



---

# 5. 数值字段分析


## 5.1 Quantity购买数量分析


分析发现：

Quantity字段存在负值。


异常情况：

- Quantity < 0


业务解释：

负数量可能代表：

- 商品退货
- 订单取消



因此：

清洗规则：

保留：

Quantity > 0



---

## 5.2 UnitPrice商品价格分析


分析发现：

UnitPrice字段存在负值。


异常情况：

- UnitPrice < 0


业务解释：

正常销售商品价格不应为负数。


因此：

清洗规则：

保留：

UnitPrice > 0



---

# 6. 交易结构分析


该数据属于订单明细数据。


一笔订单可能包含多个商品。


例如：

InvoiceNo:

536365


可能包含：

- 商品A
- 商品B
- 商品C


因此：

数据行数 ≠ 订单数量。


订单数量需要通过：

唯一InvoiceNo数量

进行计算。



---

# 7. 数据清洗策略


根据EDA结果，制定以下清洗规则：


|问题|处理方式|
|-|-|
|商品名称缺失|删除|
|负数量交易|删除|
|负价格交易|删除|
|重复数据|检查处理|
|销售额计算|Sales = Quantity × UnitPrice|



---

# 8. EDA关键发现


通过探索性分析发现：


1. 数据集包含超过54万条交易记录，具有较高分析价值。


2. 数据包含订单、商品、客户和市场多个维度。


3. CustomerID存在较高缺失比例，需要谨慎处理。


4. Quantity和UnitPrice存在异常负值，需要进行业务规则清洗。


5. 数据清洗后可用于销售趋势、商品分析和市场分析。



---

# 9. 总结


EDA阶段帮助项目理解原始交易数据结构，并发现潜在数据质量问题。


基于EDA结果，本项目建立数据清洗流程：

原始数据

↓

数据质量处理

↓

生成可靠分析数据

↓

开展商业销售分析


EDA为后续销售指标分析和商业洞察提供基础。
